# Issue #118 — finality-aware did:ethr event-history caching

## Context

Issue #118 is a Medium-severity performance enhancement. `DidEthrMethod.ResolveFromChainAsync`
always calls ERC-1056 `changed(identity)` and then `WalkEventChainAsync` issues one sequential
`eth_getLogs` request for every asserted history block, even when those blocks are finalized and
immutable. The Ethereum Execution API defines the `finalized` block tag as the most recent
crypto-economically secure block, while allowing endpoints/chains that cannot serve the tag to
return an error. Caching must therefore be opt-in, must fall back to the uncached walk when finality
is unavailable, and must never cache head events above the finalized watermark.

The cache trust boundary will store frozen raw `EthereumLogEntry` blocks, not already-trusted typed
events. Every cache read will pass those logs through the same block validator as freshly fetched
logs, preserving registry, identity, block-number, log-index, parsing, `previousChange`, count, and
byte-budget checks. The cache key will bind chain ID, registry address, and identity address.

Out of scope:

- Resolver-result TTL caching (`NetDidBuilder.AddCaching`) remains separate; it caches complete DID
  resolution results and has different invalidation semantics.
- Write paths (`Update`/`Deactivate`) remain unchanged; the next resolution observes their new
  `changed()` pointer and walks only the post-watermark segment.
- Confirmation-depth heuristics are excluded: an unavailable `finalized` tag disables this
  optimization instead of treating a probabilistic depth as indefinite immutability.
- Block-timestamp memoization remains per-resolution; issue #118 targets repeated `eth_getLogs`
  traversal, not metadata timestamp calls.

## Review

### Implementation and acceptance evidence

- Branch/base: `feat/issue-118-finalized-event-cache` from `main` at
  `7a06ae26576e394cd3f332a34b2f8b9f0ac68d7f`.
- Fail-first evidence: before production implementation, the focused issue test project failed to
  compile because `CachedEthrEventHistory` did not exist. The implemented focused suite now passes
  18/18.
- An unchanged second resolution still calls `changed(identity)` but makes no `eth_getLogs` calls
  for blocks at or below the cached finalized watermark.
- A new event above the watermark is fetched and applied immediately, and is fetched again on a
  later resolution until it becomes finalized.
- Cache use remains default-off; unsupported/malformed/null `finalized` responses fall back to the
  complete uncached walk.
- Cached raw logs re-enter the existing fail-closed validator. Foreign registry/identity data,
  duplicate `logIndex`, invalid `previousChange`, incomplete prefixes, and oversized raw payloads
  resolve as `internalError` rather than returning a partial DID document.
- The resolver-owned cache is keyed by chain/registry/identity, skips empty prefixes, rejects stale
  watermark regression, retains only finalized raw blocks, caps raw per-resolution retention at
  32 MiB, and caps aggregate cache size at 64 MiB.

### Adversarial review

Three independent reviewers examined RPC/API compatibility, cache correctness/concurrency, and the
cache trust boundary. Confirmed findings were fixed: cancellation could be swallowed by the optional
finality lookup; the first design used a caller-shared/unbounded cache; empty identities and stale
writers could amplify/regress entries; cached ABI data was decoded before its raw-size preflight;
cache failures could affect resolution; and raw logs were retained even when caching was disabled or
above finality. The final focused re-attack returned a clean verdict with no remaining blocker.

### Behavior diff from `main`

`main` always replays every asserted ERC-1056 block. This branch preserves that default and adds an
explicit DI opt-in that reuses only a validated, finalized history prefix. Public four-argument
`DidEthrMethod` construction and existing one-argument `AddDidEthr` overloads retain their uncached
behavior. Write/deactivate paths and package versioning are unchanged.
