# Issue #145: an unpaired-surrogate member name resolves `notFound` instead of `invalidDidLog`

## Context

A lone UTF-16 surrogate escape (`"\uD800"`) in a JSON member **name** makes `JsonDocument.Parse` with `AllowDuplicateProperties = false` throw `InvalidOperationException`. The parser has to decode every name to compare names for duplicates. A plain `JsonException` catch therefore misses it. Resolution still fails closed. The only problem is the wrong error code. Severity: **Low**, milestone 3.3.0.

I checked every boundary the issue lists. A scratch probe on .NET 10 against the real assemblies gave these results (`/private/tmp/claude-501/-Users-moises-Projects-net-did/62302468-cb53-4fba-8b83-96c5e6425768/scratchpad/probe145/Program.cs`):

## Review

### Outcome
The issue's defect is fixed at both boundaries that leaked it:
- `LogEntrySerializer.DeserializeEntry` (did:webvh): `notFound` → `invalidDidLog`; Update/Deactivate: raw `InvalidOperationException` → `FormatException`.
- `DidDocumentSerializer.RejectDuplicateMembers` (Core): raw `InvalidOperationException` → `JsonException`.

The adversarial pass found three more paths of the same class, all fixed in this PR:

| # | Severity | Finding | Fix |
|---|---|---|---|
| F1 | Low | A lone surrogate in a did:webvh value the typed model never reads (an unknown `publicKeyJwk` member) was first decoded while the entry was re-serialized for hashing, so it still resolved `notFound` (also for historical requests via the tail scan). | `RequireDecodableStrings` decodes every string once inside `DeserializeEntry`'s mapped try. |
| F3a | Low | A raw (unescaped) lone surrogate char in `DidDocumentSerializer.Deserialize(string)` / `DataIntegrityProofValue.Parse(string)` threw `ArgumentException` (UTF-8 transcoding). | Map `ArgumentException` (not `ArgumentNullException`) to `JsonException`. |
| F3b | Low | `Deserialize(ReadOnlySpan<byte>)` silently accepted ill-formed UTF-8 (a WTF-8 surrogate, or `0xFF` beside `0xFE`) in nested extension names, because the duplicate check compared raw bytes. The document then could not be round-tripped. | `Utf8.IsValid` before parsing. |

The pass also confirmed that claims A (all webvh name positions and lines), C (no other unguarded duplicate-rejecting parse is reachable) and D (the widened catch wraps only `Parse`) held.

Three further findings were pre-existing, in other subsystems. At the user's direction ("fix them as part of this issue") they are fixed in this PR; see Round 3 below.
