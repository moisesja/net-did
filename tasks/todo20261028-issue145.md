# Issue #145: an unpaired-surrogate member name resolves `notFound` instead of `invalidDidLog`

## Context

A lone UTF-16 surrogate escape (`"\uD800"`) in a JSON member **name** makes `JsonDocument.Parse` with `AllowDuplicateProperties = false` throw `InvalidOperationException`. The parser has to decode every name to compare names for duplicates. A plain `JsonException` catch therefore misses it. Resolution still fails closed. The only problem is the wrong error code. Severity: **Low**, milestone 3.3.0.

I checked every boundary the issue lists. A scratch probe on .NET 10 against the real assemblies gave these results (`/private/tmp/claude-501/-Users-moises-Projects-net-did/62302468-cb53-4fba-8b83-96c5e6425768/scratchpad/probe145/Program.cs`):

**Out of scope, with reasons:**
- Parses that allow duplicates (`DidWebVhMethod.cs:125`, `ScidGenerator.cs:35/55`, `LogChainValidator.cs:361`, `WitnessValidator.cs:309`, `LogEntrySerializer.cs:164`) only see library-serialized JSON. Every caller-supplied lone surrogate is replaced with U+FFFD, and `Serialize` throws `JsonException` for a lone-surrogate name inside `AdditionalProperties` (probe confirmed).
- did:peer (`Numalgo2ServiceEncoder.cs:83`, `Numalgo4Handler.cs:117`): `DidPeerMethod.cs:87` already maps every exception to `invalidDid`, so the error code is already uniform.
- did:ethr RPC: the envelope (`DefaultEthereumRpcClient.cs:383`) and per-log parsing (`:114`) already catch `InvalidOperationException`.
