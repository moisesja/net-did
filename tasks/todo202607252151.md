# did:ethr Phase 2 — on-chain write path (Update / Deactivate / meta-tx / deployment / integration tests)

## Context

did:ethr ships Create + Resolve only (`Capabilities = Create | Resolve | ServiceEndpoints`); `UpdateAsync`/`DeactivateAsync` throw `OperationNotSupportedException`. The PRD (§8.6–§8.8, §16 Phase 4) plans full CRUD: RLP transaction construction, ABI write calldata, RPC write methods, meta-transactions, deactivation, and live-network integration tests. This task implements all of it, including answers to the two structural questions: **how to mock a blockchain** and **how to deploy the ERC-1056 registry contract**.

### Exploration findings that shape the design

1. **NetCrypto 1.3.0 already ships the Ethereum signing primitive.** `NetCrypto.Secp256k1Recoverable.Sign(privateKey, digest32)` → 64-byte R‖S + raw recovery id; RFC 6979 deterministic; **low-S normalized**; signs the caller's digest as-is (its doc explicitly says "for did:ethr / EVM flows that digest is Keccak-256… EVM v-encoding is the wallet layer's responsibility"). `RecoverPublicKey(digest, sig, recid, compressed)` gives real `ecrecover`. **No crypto-dotnet changes needed.**
2. **The generic `ISigner` cannot sign Ethereum transactions.** `DefaultCryptoProvider.SignSecp256k1` SHA-256-hashes internally (ES256K) and returns no recovery id ([crypto-dotnet DefaultCryptoProvider.cs:435-453](file:///Users/moises/Projects/crypto-dotnet/src/NetCrypto/DefaultCryptoProvider.cs)). ⇒ `DidEthrUpdateOptions.ControllerKey : ISigner` must change type. All did:ethr API is **unreleased** (`[Unreleased]` CHANGELOG, precedent: the `LogIndex` required-member note), so this is allowed with a CHANGELOG entry.
3. **Meta-tx preimages verified against both deployed contract sources** (fetched from `uport-project/ethr-did-registry`):
   - Preimage: `keccak256( 0x19 ‖ 0x00 ‖ registry(20) ‖ nonce(32) ‖ identity(20) ‖ "methodName"(ASCII) ‖ packed args )` — `abi.encodePacked`: address=20B, uint=32B, bytes32=32B, string/bytes=raw.
   - **Modern 1.x** (pragma 0.8.6; `0x03d5003b…`; `LegacyNonce=false`): all five preimages read `nonce[identityOwner(identity)]`; `checkSignature` requires `signer == identityOwner(identity)` and increments `nonce[signer]`.
   - **Legacy v0.0.3** (pragma 0.4.4; mainnet `0xdca7…`; `LegacyNonce=true`): `checkSignature` increments **`nonce[identity]`**; preimage reads `nonce[identityOwner(identity)]` for changeOwner/addDelegate/revokeDelegate but **`nonce[identity]`** for setAttribute/revokeAttribute. `EthereumNetworkConfig.LegacyNonce` finally gets consumed.
   - `addDelegate` stores/emits `validTo = block.timestamp + validity`; `revokeDelegate` emits `validTo = block.timestamp`; `revokeAttribute` emits `validTo = 0`; every mutation sets `changed[identity] = block.number` — matching what the resolver already replays.
4. Reusable pieces: `AbiEncoder.IdentityOwnerCalldata` + `Erc1056Calls.IdentityOwner` exist unused (pre-flight owner check); `ResolveChainId` (EIP-155 chain id); `DefaultEthereumRpcClient.SendAsync` envelope with response caps; the resolver deadline pattern; `EthereumAddress.FromCompressedPublicKey`; `DefaultKeyGenerator.FromPrivateKey` (Anvil dev keys); capabilities enum has `Update = 4, Deactivate = 8`.
5. `DidUpdateResult` requires `DidDocument` and takes `Artifacts` (PRD explicitly names "tx hash for ethr" as an artifact). `DidDeactivateResult { Success, Artifacts }`.

## The two big questions

### Q1 — How do we mock a blockchain? Three layers, each with an honest oracle

- **L0 — external known-good vectors (no node).** RLP + EIP-155 signing pinned against the canonical EIP-155 test vector (nonce 9 / gasPrice 20 gwei / key `0x4646…46` → published signing hash + signed raw hex, v=37) plus a real mainnet raw tx (decode → recover sender → compare known from-address). Avoids the writer/reader-parity trap (`tasks/lessons.md`): our encoder is checked against *published* bytes, not our own decoder.
- **L1 — in-memory ERC-1056 node (default test suite + sample).** New non-packed project `tests/NetDid.Method.Ethr.Emulator/` referenced by the unit tests, the integration tests, and the sample (single implementation — no duplication with the sample's current read-only registry, which it replaces). It behaves like a real node at the protocol boundary: `eth_sendRawTransaction` → RLP-**decode** (emulator-side decoder) → recompute the EIP-155 signing digest → **real ecrecover** (`Secp256k1Recoverable.RecoverPublicKey`) → derive sender via `EthereumAddress` → enforce nonce, chain id, low-S → execute the ERC-1056 semantics transcribed from the verified contract source (both nonce modes, constructor-selectable) → mint blocks/logs/receipts with correct `previousChange` linkage. No test back-doors: authorization comes from signature recovery, exactly like the chain.
- **L2 — a real EVM (opt-in integration).** `tests/NetDid.Method.Ethr.IntegrationTests/` using **Testcontainers for .NET + the `ghcr.io/foundry-rs/foundry` image running `anvil`**. Anvil over Ganache/Hardhat (PRD's 2023-era suggestions): single static binary, fastest startup, maintained. Tests deploy the *real registry bytecode* and run the full lifecycle — the true conformance oracle, and the only place meta-tx preimages are proven against the actual contracts. Gated by `NETDID_ETHR_INTEGRATION=1` + Docker present (custom `FactAttribute` that sets `Skip` otherwise), so `dotnet test netdid.sln` stays offline-green and the verify gate is unchanged.

### Q2 — How do we deploy the ERC-1056 registry?

- **Public networks: never.** The registry is already deployed at well-known addresses — that is `KnownNetworks`' whole purpose (12 chains, registry + chainId + `legacyNonce` pre-populated).
- **Dev/private chains: a shipped deployer.** New `Deployment/Erc1056Registry` in `NetDid.Method.Ethr` embedding the **compiled creation bytecode of both deployed contract generations** — modern `ethr-did-registry@1.3.0` and legacy `@0.0.3` — vendored from the published npm artifacts with provenance pinned (package version, source URL, MIT license header, and a unit test asserting the keccak256 of each embedded artifact). `DeployAsync(rpc, signer, chainId, ct)` sends a contract-creation transaction (RLP `to` = empty) **through our own transaction pipeline** and returns `receipt.contractAddress`. Used by the integration tests on Anvil; documented in the README for private/consortium EVM chains. Users then run `new EthereumNetworkConfig { RegistryAddress = deployed, … }`.

## Implementation

All in `src/NetDid.Method.Ethr` unless noted. **No `NetDidVersion` bump** (release rule).

### P0 — Upstream: `IRecoverableDigestSigner` in NetCrypto 1.4.0 (crypto-dotnet)
User decision: the digest-signer abstraction lives upstream, next to the `Secp256k1Recoverable` primitive it wraps (precedent: `ToUncompressed`, crypto-dotnet#19 → 1.3.0).
- File a crypto-dotnet issue; branch; add:
  - `public interface IRecoverableDigestSigner { KeyType KeyType { get; } byte[] PublicKey { get; } Task<(byte[] Signature64, int RecoveryId)> SignDigestAsync(ReadOnlyMemory<byte> digest32, CancellationToken ct = default); }`
  - `KeyPairSigner` and `KeyStoreSigner` implement it for `KeyType.Secp256k1` by delegating to `Secp256k1Recoverable.Sign` (KeyPair path via `WithPrivateKey`; key-store path via a store-internal digest-sign — `InMemoryKeyStore` holds the `KeyPair`); other key types throw `NotSupportedException`. External `IKeyStore` implementors stay source-compatible (any new `IKeyStore` member ships as a DIM default that throws, documented as the opt-in for EVM flows).
  - **No keccak, no EVM `v`-encoding** — preserves the FR-12 boundary ruling verbatim (raw recid 0–3 only).
  - PublicAPI.txt entries, XML docs, unit tests (sign→recover round-trip, low-S, non-secp256k1 throws).
- Release NetCrypto **1.4.0** (crypto-dotnet's release flow), then bump `Directory.Packages.props` here to 1.4.0.
- net-did types `ControllerKey`/`Relayer` against `NetCrypto.IRecoverableDigestSigner`; keccak + EIP-155 `v`-encoding stay in `NetDid.Method.Ethr`.

### P1 — Transaction primitives (`Transactions/`)
- `RlpEncoder`: byte-string/list items, minimal big-endian integers (zero = empty string), length prefixes. Internal-visible for tests.
- `EthereumTransaction` record (legacy type-0): `Nonce, GasPrice, GasLimit, To (null ⇒ contract creation), Value, Data, ChainId`. Methods: EIP-155 signing payload `rlp([n,gp,gl,to,v,data,chainId,0,0])`, `SigningDigest` (keccak), `Encode(signature64, recid)` → raw signed rlp with `v = 35 + 2·chainId + recid`, `Hash`.
- `Transactions/EthereumTransactionSigner`: binds an `IRecoverableDigestSigner` to a transaction — computes the keccak signing digest, calls `SignDigestAsync`, applies EIP-155 `v`-encoding, derives the sender address from `PublicKey` (via `EthereumAddress`). This is the net-did-side "wallet layer" the FR-12 remark assigns.
- Unit tests: EIP-155 canonical vector byte-for-byte; RLP edge vectors (0, 0x7f, 0x80, 55/56-byte strings, empty list — from the Ethereum RLP test suite); recover-sender round-trip on a known mainnet raw tx.

### P2 — RPC write surface (`Rpc/`)
- `IEthereumRpcClient` +`GetTransactionReceiptAsync(string txHash)` → `EthereumTransactionReceipt? { Status, BlockNumber, TransactionHash, ContractAddress? }` (null while pending), +`EstimateGasAsync(string from, string? to, string data)`. Implement these plus the three existing stubs (`SendRawTransactionAsync`, `GetTransactionCountAsync` ("pending"), `GetGasPriceAsync`) in `DefaultEthereumRpcClient` with the same canonical-hex validation and response caps as the read methods. CHANGELOG notes the unreleased-interface additions.
- +`NonceCalldata(address)` in `AbiEncoder` (`nonce(address)` getter, needed for meta-tx).

### P3 — Direct Update / Deactivate
- `Abi/AbiEncoder`: `EncodeUint256`, `EncodeBytes32(string)`, dynamic-`bytes` head/tail encoding; `Erc1056/Erc1056TransactionBuilder`: calldata for `changeOwner`, `addDelegate`, `revokeDelegate`, `setAttribute`, `revokeAttribute` (selectors keccak-computed at init like `AbiEncoder`'s existing ones).
- `DidEthrMethod`: `Capabilities` += `Update | Deactivate`; `UpdateCoreAsync`/`DeactivateCoreAsync`:
  1. Parse DID, find network/rpc; require ≥1 mutation; `ControllerKey` required (`IEthereumDigestSigner`).
  2. **Pre-flight**: `identityOwner(identity)` eth_call must equal the signer's address (fail fast with a clear `EthereumInteractionException`; the contract's `onlyOwner` remains the enforcement point). `ControllerKey`/`Relayer` are `NetCrypto.IRecoverableDigestSigner` (P0).
  3. Op order: attribute/delegate revokes + adds first, `NewOwnerAddress` **last** (changeOwner revokes the key's authority for subsequent txs). Deactivate = `changeOwner(identity, 0x0)`.
  4. Per op: nonce → `EstimateGasAsync` (bounded fallback cap) → `GetGasPriceAsync` → sign → send → poll receipt under an overall write deadline (linked-CTS pattern from `ResolveCoreAsync`); `Status != 1` or timeout ⇒ fail closed, reporting which ops landed (tx hashes) and which did not. Sequential, no fire-and-forget.
  5. Result: re-resolve → `DidUpdateResult { DidDocument, Artifacts = { "transactions": [hashes], "registry": address } }` / `DidDeactivateResult`.
- Options: `ControllerKey` type change `ISigner` → `NetCrypto.IRecoverableDigestSigner` in `DidEthrUpdateOptions` + `DidEthrDeactivateOptions` (unreleased API; CHANGELOG). `DidEthrCreateOptions.ExistingKey` stays `ISigner` (only needs the public key).
- Negative-state matrix designed **before** coding (lessons): wrong signer, revert (status 0), receipt timeout, mixed batch with one failing op, gas-estimate failure, `to`-less creation misuse, zero-mutation call.

### P4 — Meta-transactions
- `Erc1056TransactionBuilder`: the five `…Signed` calldata builders + the `0x19 0x00` preimage builder (verified layouts above). Nonce fetch respects `LegacyNonce`: modern ⇒ `nonce(identityOwner)`; legacy ⇒ `nonce(identityOwner)` for owner/delegate ops, `nonce(identity)` for attribute ops.
- Flow: `ControllerKey` (identity owner) signs the preimage digest; `Relayer` (**new option**, `IRecoverableDigestSigner?`, required when `UseMetaTransaction = true`) pays gas and signs the outer transaction carrying `…Signed(identity, sigV = 27 + recid, sigR, sigS, …)`.
- Emulator implements `checkSignature` for both generations; integration tests prove both against the real bytecodes.

### P5 — Deployment + integration tests
- `Deployment/Erc1056Registry` (+ two embedded `.bin` resources with provenance + hash-pinning test) and `DeployAsync` as in Q2.
- `tests/NetDid.Method.Ethr.IntegrationTests/` (Testcontainers, env-gated): Anvil container; fund/derive accounts from Anvil's well-known dev keys via `DefaultKeyGenerator.FromPrivateKey`; deploy both registries with our deployer; matrix: full CRUD lifecycle → resolve after each write (delegates/services/expiry/owner change/deactivation), `?versionId` replay across writes, meta-tx per contract generation (incl. attribute-op legacy nonce), ETH value transfer (funds a fresh controller — exercises plain tx), deploy-then-resolve on a virgin registry.

### The two structural questions

**Mocking a blockchain — three layers, three independent oracles.** L0: published external vectors (EIP-155 canonical example, Yellow Paper RLP, 4byte.directory selectors) — never writer/reader parity. L1: an in-memory chain that strictly RLP-decodes real signed transactions, recovers senders with real `ecrecover`, and enforces chain id / nonce / low-S — no test back-doors. L2: Anvil via Testcontainers running the real registry bytecode, env-gated so the default suite stays offline.

**Deploying the registry.** Never on public networks (`KnownNetworks` has the addresses). For private chains, `Erc1056Registry.DeployAsync` ships both generations' creation bytecode, vendored from the official npm artifacts and keccak-pinned. Independently verified during review: byte-exact against npm, and their runtime bytecode byte-exact against `eth_getCode` at the live mainnet and Sepolia registries.

### Adversarial review — 23 findings across 3 rounds, all fixed

Round 1 (4 lenses: crypto/signing, trust-boundary, emulator fidelity, supply-chain/API/docs) → 14 findings. Round 2 (re-attack on the fixes) → 9 residuals, three of them *in the fixes themselves* and one *over-strict*. Round 3 pending at time of writing.

Highest severity:
- **Legacy-registry meta-tx replay (HIGH)** — v0.0.3 increments `nonce[identity]` but owner/delegate preimages read `nonce[identityOwner]`; after a transfer the preimage nonce never moves and calldata replays forever. Refused, scoped precisely to the vulnerable operations.
- **"Deactivation is irreversible" was FALSE (HIGH)** — the registry's `identityOwner()` is `owner != 0 ? owner : identity`, so zeroing hands control back to the identity. The **spec claims otherwise**; the deployed contract is the authority. Docs corrected; the emulator had hidden this and was corrected too.
- **A single Update could permanently brick a DID (HIGH)** — an undecodable `did/pub/…` value threw out of the document builder → `notFound` for the whole DID for the attribute's 10-year validity. Now degrades one entry.
- **Unbounded spend (HIGH→MEDIUM)** — gas price was signed verbatim from the untrusted node; then bounding price and limit separately still allowed 15 ETH/tx. Both a price ceiling and a total-fee ceiling.
- **Mid-batch evidence loss (MEDIUM-HIGH)** — callers were told nothing landed while transactions sat on-chain; fixed twice (the first fix only relocated the gap into its own new post-batch read).

Every exploit file is retained, inverted, as a regression test.

### Deliberate non-goals / documented residuals

- **Cross-chain meta-tx replay** — the ERC-1056 preimage binds the registry address but no chain id, and one registry serves several chains. Not client-fixable; documented with the concrete attack.
- **Deactivation is not a lock** — inherent contract behavior, now documented rather than papered over.
- **Emulator cannot model gas** — a permanent blind spot; the Anvil suite is the gas oracle.
- **EIP-1559 typed transactions** — out of scope; legacy type-0 is accepted by every `KnownNetworks` chain.
