# Issue #110 — DataProofsDotnet.Core 0.1.0-preview.1 → 1.1.1

## Context

`Directory.Packages.props` pinned `DataProofsDotnet.Core` at a **pre-1.0 preview** while 1.1.1
was published — five releases, crossing a major, under the library that produces and verifies
every `did:webvh` Data Integrity proof.

Verified up front that this was **staleness, not an incident**: `dotnet list package
--vulnerable --include-transitive` was clean across all 20 projects; the `AngleSharp` advisory
fixed in 1.1.1 reaches consumers through `DataProofsDotnet.Rdfc` → `dotNetRdf.Core`, which
net-did does not reference; and the 1.0.1/1.1.1 `JwsParser` fixes are in the JOSE package, which
net-did does not consume.

## Plan

- [x] Capture a `did.jsonl` + `eddsa-jcs-2022` proof from the **pre-upgrade** library as a
      committed fixture, before bumping.
- [x] Add upgrade guards and prove they pass on the OLD version (so they measure the bump).
- [x] Bump to 1.1.1; build; run the full suite.
- [x] Verify the three documented hazards explicitly.
- [x] CHANGELOG under `[Unreleased]`; **no `NetDidVersion` bump**.
- [x] Open PR, stop before merge.

**No source change was required.** The bump is source-compatible: 0 errors, 0 warnings, and no
existing assertion was relaxed.

### Hazards, checked explicitly rather than inferred from a green build

| Hazard | Result |
|---|---|
| Wire drift — a proof written by preview.1 | Still verifies (`ProofWrittenByThePreUpgradeLibrary_StillVerifies`) |
| `Base64Url.Decode` strict since 1.0.0 | Malformed `proofValue` (padding / whitespace / `+`) → resolution error, never a raw `FormatException` |
| Proof-`type` dispatch + Legacy suites added in 1.0.0 | A legacy `Ed25519Signature2020`-typed proof is still **rejected** — accepted cryptosuite set has not widened |
| Tampered proof | Still fails verification |
| NetCrypto floor (1.0.0 raised it to 1.1.0) | We are on 1.4.0; no downgrade warning, no `Base64Url` type ambiguity |
| Transitive `AngleSharp` / `dotNetRdf` | Still absent after the upgrade; vulnerable audit clean |

### Not verified in this run

The Anvil integration suite (`NETDID_ETHR_INTEGRATION=1`) could **not** be re-run: Docker is
unavailable in this environment. It is provably independent of this change —
`NetDid.Method.Ethr.IntegrationTests` references only `NetDid.Method.Ethr`, which has **zero**
DataProofs references (DataProofs is consumed solely by `NetDid.Method.WebVh`). It was 7/7 green
earlier in the session on the same did:ethr code, which this PR does not touch.

### Follow-up noticed, deliberately not folded in

`EthrIntegrationFactAttribute` gates only on the env var, so with `NETDID_ETHR_INTEGRATION=1`
set and Docker down the suite **fails** rather than skipping. `README`/`net-did-verify` describe
it as skipping cleanly when Docker is absent, so the documentation overstates the behaviour.
Small, but it is a false claim I introduced in #107 — worth its own issue rather than scope creep
here.
