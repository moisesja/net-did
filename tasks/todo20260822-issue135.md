# Issue #135 — did-witness.json wire-format conformance (`proofs` → `proof`, + signed-data model)

## Context

Issue #135 (Critical): `did-witness.json` is written and parsed with a `proofs` member, but did:webvh v1.0 and all 6 reference implementations use `proof`. Result: no witnessed DID interoperates in either direction; all 10 witnessed DIF-suite replays are rejected as `witnessValidationFailed`, and the parse failure is swallowed by a blanket `catch` so there is no diagnostic.

**Assessment confirmed the report and found a second, deeper wire divergence the issue does not name:**

- Confirmed: write at `src/NetDid.Method.WebVh/WitnessValidator.cs:196` (`WritePropertyName("proofs")`), read at `:272` (`GetProperty("proofs")`), blanket `catch { return null; }` at `:263-266`. All 14 committed suite `did-witness.json` files use `proof`.
- **New finding — witness signed-data model is also wrong.** NetDid verifies witness proofs against `LogEntrySerializer.SerializeWithoutProof(entry)` (`WitnessValidator.cs:42,135`). The spec says witness proofs "use the `versionId` as input data". I empirically verified suite witness proofs from **ts, rust, java, dart**: every proof verifies over the JCS document `{"versionId": "<versionId>"}` and **fails** over entry-without-proof (script: eddsa-jcs-2022, SHA-256(JCS(proofConfig)) ‖ SHA-256(JCS(doc))). Fixing only the key name would leave all 10 witnessed replays still rejected — both defects must be fixed to resolve the issue's stated impact.
- Security soundness of `{"versionId": ...}` signing: `versionId = <n>-<entryHash>` and chain validation independently recomputes the entry hash over full entry content *before* witness validation runs, so a witness approval transitively binds the whole entry.

**Deliberate decision — no tolerant read of legacy `proofs`:** witness proofs minted under the old model are signed over the wrong document, so the corrected validator (and every conformant implementation) rejects them regardless of key name. A migration read of the `proofs` key can never validate; previously published NetDid witness files must be re-witnessed. Clean break, documented as breaking in CHANGELOG.

Severity: High/Critical (matches issue).

**Out of scope** (each is a separate concern, none affects this fix):
- `LogEntrySerializer.cs` log-entry `proof` handling — already spec-correct (issue confirms).
- Error-code vocabulary divergences (`invalidDidLog` vs suite's `invalidProof` etc.) — tracked by the report §C; the legacy-code decision is issue #123 territory.
- The `python` vectors' missing-`controller` rejections (report §E) — unrelated divergence, separate issue.
- Witness *policy* validation (`WitnessPolicyValidator`) — not wire-format, unchanged.
