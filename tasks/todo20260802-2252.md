# Issue #119 — did:ethr archive-node docs + opt-in RPC auto-configuration with endpoint probing

## Context

`KnownNetworks` catalogues the official ERC-1056 deployments but every entry ships `RpcUrl = ""`, and nothing documents that did:ethr resolution requires an endpoint serving **historical `eth_getLogs`** (archive-grade). Users on pruned free-tier endpoints get opaque resolve-time failures. The reference-resolver maintainer's guidance (quoted in the issue): probe candidate public endpoints with known-old DIDs and discard any that return empty logs. Their companion JS library is **not yet published** (verified by web search 2026-08-02), so our probe data is designed to be alignable later, per the issue's own suggestion.

Assessment confirmed against source:
- `src/NetDid.Method.Ethr/Rpc/KnownNetworks.cs:8-13,152-156` — empty `RpcUrl`, `with {}` instruction, no quality guidance.
- `src/NetDid.Method.Ethr/Rpc/EthereumNetworkConfig.cs:7` — `RpcUrl` XML doc says nothing about archive requirements.
- `src/NetDid.Method.Ethr/DidEthrMethod.cs:597-604` — walker fails closed (`IncompleteEventHistoryException`) when an asserted block has no logs; mapped at `:216-232` to `internalError` with "pruned/non-archive" text. Detection exists, but only at resolve time, per DID.
- Live demonstration of the failure class: `https://ethereum-rpc.publicnode.com` answers `eth_chainId` fine but rejects a historical `eth_getLogs` with "Archive requests require a personal token" — a liveness check alone passes an unusable endpoint.
- Real probe data is obtainable and verifiable: mainnet legacy registry (`0xdca7ef03…`) has ERC-1056 events for identity `0xf87e64e1fd8098fde28fb0852459dc839f35de94` at blocks 10,001,725/10,001,739 (May 2020), confirmed via `eth_getLogs` on `eth.drpc.org` during assessment.

Severity: Medium (documentation gap + missing batteries-included setup; failures are already fail-closed, never silent truncation).

## Approach decision

Implement the helper **inside `NetDid.Method.Ethr`** as a static class, not a new package. The package already references `Microsoft.Extensions.Logging.Abstractions` + `Microsoft.Extensions.Http`, and probing reuses the existing hardened `DefaultEthereumRpcClient` (response caps, bounded error extraction) — so acceptance criterion "no new mandatory dependencies" is met with zero packaging overhead. The issue explicitly allows "a static helper".

Registration in DI is eager/synchronous (`NetDidBuilder.AddDidEthr`, `src/NetDid.Extensions.DependencyInjection/NetDidBuilder.cs:103`), so the helper is a **probe-first, then register** bootstrap: caller awaits it, gets ready `EthereumNetworkConfig`s, hands them to the existing `AddDidEthr(IEnumerable<EthereumNetworkConfig>)` or `DidEthrMethod` ctor. No DI changes needed.

## Plan

### 1. New: `src/NetDid.Method.Ethr/Rpc/EthrRpcAutoConfig.cs`

```csharp
public static class EthrRpcAutoConfig
{
    // Built-in candidate public endpoints for major official deployments
    // (mainnet, sepolia, gnosis, polygon — each verified working at implementation time).
    public static IReadOnlyDictionary<string, IReadOnlyList<string>> DefaultCandidateEndpoints { get; }

    public static Task<IReadOnlyList<EthereumNetworkConfig>> ConfigureAsync(
        IReadOnlyDictionary<string, IReadOnlyList<string>>? candidateEndpoints = null, // null => defaults
        ILogger? logger = null,
        TimeSpan? perEndpointTimeout = null,   // default ~10 s; owned HttpClients, so both directions work
        CancellationToken ct = default);
}
```

Behavior per network (keys resolved via `KnownNetworks.Find`; unknown names rejected with a logged reason):
1. Snapshot the caller-supplied dictionary/lists ONCE at entry (interface-typed input = adversarial; lessons).
2. For each candidate URL **sequentially, first-healthy-wins** (minimizes traffic; deterministic):
   a. `eth_chainId` must equal the network's `ChainId` → else discard, log fixed-text reason + the URL.
   b. **Historical-logs probe**: `eth_getLogs` on the network's registry address filtered to a hard-coded known-old identity + small block window (`HistoricalLogProbe` record: identity, fromBlock, toBlock; window ≤ a few hundred blocks to stay under provider range limits). Non-empty → endpoint passes; empty or RPC error → discard, log fixed-text reason.
3. Network with a passing endpoint → emit `KnownNetworks.<X> with { RpcUrl = url }`.
4. Network with **no probe data** (we only hard-code probes we can verify on-chain) → chain-ID check only; emit config but log a warning that archive-grade serving is unverified.
5. Network with no passing candidate → omitted from the result, logged.
6. Overall: token checked before/after every RPC await (per-dependency-await symmetry lessons); per-endpoint failures never abort the whole run; logging guarded with a final swallow (never-throw precedent of `LogResolveFailure`); log text is fixed library-owned strings + the candidate URL (caller/library-supplied) — never response content.

Probe table: hard-code only entries verified live during implementation via real `eth_getLogs` (mainnet entry above; attempt the same for sepolia/gnosis/polygon and include whichever verify). Each entry carries a comment citing the verification (identity, block, date checked). **No fabricated on-chain data** (emulator/mock lessons).

Testability seam: `internal` overload accepting `Func<EthereumNetworkConfig, IEthereumRpcClient>` (per-candidate client factory), used via existing `InternalsVisibleTo NetDid.Method.Ethr.Tests`. Public path builds one owned `DefaultEthereumRpcClient` per candidate URL (`HttpClient { BaseAddress, Timeout }`), disposed after probing.

Trust property documented on the class: probing verifies **availability/quality only** — a passing endpoint is still a single untrusted RPC node that can forge self-consistent history (the library's existing documented integrity property).

### 3. Tests — `tests/NetDid.Method.Ethr.Tests/Issue119AutoConfigTests.cs`

`Issue119_*` naming, box-banner grouping, NSubstitute `IEthereumRpcClient` via the internal seam, hand-rolled recording logger (Issue116 style — repo has no FakeLogger package):
- pruned endpoint (chainId OK, `GetLogsAsync` → empty) → discarded + logged actionable reason (acceptance criterion 3).
- wrong chainId → discarded.
- RPC error / cancellation-ignoring hang (via timeout) → discarded, run continues to next candidate.
- healthy endpoint → config emitted with that URL; earlier-listed healthy endpoint wins.
- network without probe data → emitted with unverified warning.
- no passing candidate → network omitted + logged.
- caller cancellation propagates (including mid-probe).
- hostile snapshot: candidate list mutating between enumerations → probed set is the entry snapshot.
- throwing logger → helper still completes (guarded logging).
- `DefaultCandidateEndpoints` covers only networks present in `KnownNetworks.All`.

Feature tests are fail-first trivially (surface doesn't exist before the change); noted in the Review section rather than stash-proven.

## Out of scope (justified)

- New `NetDid.Method.Ethr.AutoConfig` package — unnecessary; zero new deps in-package satisfies the criterion the package split existed to protect.
- Aligning probe DIDs with the maintainer's companion library — not yet published; probe table is data-driven so a follow-up can swap entries. Tracked in the issue itself ("track when published").
- Changing resolve-time error surfacing (`internalError` vs `notFound`) — companion issue, separate scope.
- Sample changes — auto-config requires live network; samples must keep running offline for `net-did-verify`.
- Background re-probing / caching of probe results — bootstrap-time helper only; callers re-run it on their own schedule.
