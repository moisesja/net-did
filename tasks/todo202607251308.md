# Issue #105 — did:ethr example project + stale documentation

## Context

`did:ethr` landed via PR #104 (merged, `8b86db4`), but two artifacts were never brought up to date:

1. **The sample is a stub.** [samples/NetDid.Samples.DidEthr/Program.cs](samples/NetDid.Samples.DidEthr/Program.cs) is 62 lines and exercises exactly two paths — resolve-latest and `?versionId=0` — against a live public endpoint (`https://sepolia.drpc.org`, line 9). Because the fixture is a real testnet DID with no on-chain history, the sample **cannot** show delegates, attribute keys, services, owner change, deactivation, expiry, or any error path. It is also network-dependent, so it is absent from the `net-did-verify` §4 smoke-test list while every other method sample is present. The peer/webvh/key samples run 138–229 lines offline; [samples/NetDid.Samples.DidWebVh/Program.cs:217](samples/NetDid.Samples.DidWebVh/Program.cs#L217) establishes this repo's convention for a network-backed method: an in-memory implementation of the method's transport interface.

### Self-review (in place of the adversarial-subagent pass)

The `adversarial-review` trigger ("security-sensitive change: crypto, key handling, log
validation, serialization, parsing, trust boundaries") does not fire — no such code is touched.
The targeted risk for this diff is a *fixture that lies*: an in-memory RPC client that routes
around the resolver hardening would make the sample a false advertisement. Checked
point-by-point against `DidEthrMethod.WalkEventChainAsync`, the fixture **satisfies** rather
than bypasses every fail-closed invariant:

- logs carry the configured `RegistryAddress` → the foreign-registry check passes legitimately;
- every event's identity topic is the scripted identity → the foreign-identity check passes;
- `LogIndex` is unique and ascending per block → the duplicate-index check passes;
- `blockNumber` is emitted as a canonical quantity (`0x64`, not `0x064`);
- the first event of a block points at the genuinely previous block and later same-block
  events point at the current block → the ERC-1056 `previousChange` rule passes;
- `changed()` only ever asserts a block the registry serves (except in the deliberate
  negative case below).

Two narration issues were found and fixed: "that is the specified did:ethr behaviour" for
`#delegate-N` gap numbering overstated a JS-reference-resolver compatibility behaviour
(reworded), and the fail-closed claim in the error section was **asserted but not
demonstrated** — it is now an executed case (`assertedLatestBlock: 900` with no event served
at 900 → `notFound`, no partial document).
