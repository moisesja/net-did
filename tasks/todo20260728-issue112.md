# Issue #112 — did:ethr integration suite: align Docker-gate behaviour and docs (Option A: fail loudly)

## Context

Issue #112: the did:ethr integration suite's docs claim tests are "skipped unless `NETDID_ETHR_INTEGRATION=1` **(and Docker is reachable)**", but the gate (`tests/NetDid.Method.Ethr.IntegrationTests/AnvilFixture.cs:14-18`) only checks the env var. With the var set and Docker down, all 7 tests fail with seven raw `DockerUnavailableException` stack traces. The default offline run is unaffected.

**Decision: Option A (the issue's own recommendation) — fail loudly.** Setting `NETDID_ETHR_INTEGRATION=1` means "I want real-EVM coverage to run"; silently skipping when Docker is down would let a green run masquerade as coverage. Keep the env-var-only skip decision, make the Docker-unreachable failure a single actionable message, and correct every doc that implies Docker participates in the skip decision.

Severity: Low (test-harness ergonomics + doc accuracy). Facts pinned during assessment: Testcontainers 4.13.0 `DockerUnavailableException` has public `(string)` / `(string, Exception)` ctors; xunit v2 (2.9.3) reports a collection-fixture failure per test, so "surfaced once" = one Docker attempt (single collection fixture, already true) + the same single actionable message on every report.

**Simulation-method correction (found during execution):** the plan's `DOCKER_HOST=tcp://127.0.0.1:1` poisoning does NOT simulate "Docker down" — Testcontainers' endpoint detection availability-checks each provider and falls through dead endpoints to the live `/var/run/docker.sock` (root-owned symlink to Docker Desktop's socket; verified: the poisoned run passed all 7 tests against real Docker). No env knob can hide a live root-level socket, and stopping the user's daemon is off the table. Instead, "Docker unavailable" runs execute the suite **inside a `mcr.microsoft.com/dotnet/sdk:10.0` container with no Docker socket mounted** — a genuinely Docker-less environment reproducing the issue's exact failure mode end-to-end.

### Adversarial review — round 1 (2026-07-28)

Two independent worktree-isolated agents (harness-correctness lens; doc-contract lens), both prompted to refute. Findings and resolutions:

- **CONFIRMED (Medium, correctness F1)** — the `[assembly: CollectionBehavior(DisableTestParallelization = true)]` "sequential guarantees" comment was defeasible: runner config (`xUnit.ParallelizeTestCollections=true` via runsettings/xunit.runner.json) overrides the assembly attribute (agent demonstrated with a probe project on the exact package versions), re-opening the env-mutation race in principle. **Fixed at the root**: env mutation eliminated entirely — internal test-seam ctor `EthrIntegrationFactAttribute(string? optIn)`; `EnvScope` and the assembly attribute deleted; ambient-equivalence test pins public-ctor↔env delegation in every mode.
- **CONFIRMED (Medium, correctness F2 + doc-agent)** — dropping `InnerException` lost the per-endpoint failure *reason* (Testcontainers' `Details:` lines carry only "Failed to connect to …"; permission-denied vs connection-refused lives in the inner `AggregateException` chain — and "Start Docker" is the wrong remedy for a docker-group misconfiguration). **Fixed**: `DockerUnreachableFailure` appends the flattened inner-cause chain as one-line `Underlying cause: <Type>: <message>` text entries; still no exception object carried. Verified in the Docker-less container: `Underlying cause: HttpRequestException: Connection failed.` survives.
- **CONFIRMED (Medium, correctness F3)** — the tests pinned the message factory but not the wiring: deleting the try/catch kept all tests green in every locally-runnable mode. **Fixed**: the catch-and-wrap moved into `AnvilFixture.StartWithHonestDockerFailureAsync(Func<Task<IContainer>>)`; always-run tests now pin the mapping (DockerUnavailableException → actionable failure) AND the no-misdiagnosis pass-through (`TimeoutException` propagates unwrapped). Residual: the single visible line wiring `InitializeAsync` through the helper is not machine-pinned; the containerized opted-in run remains the e2e oracle.
- **CONFIRMED (Medium, doc F1; Low, F2/F4/F5)** — CHANGELOG "one … instead of seven" read as a count change (xUnit reports the fixture failure once per test — 7 failures remain, with identical message); "one-line message" was false (Testcontainers 4.13's message is multi-line by construction); "default run is unchanged" needed scoping to offline behaviour; committed task file described the abandoned `[Collection("anvil")]` design and said "7 pass" where the opted-in result is 11 (now 18). **All fixed** in CHANGELOG/task file; commit message corrected via amend.
- **Out of scope (Low, correctness F4)** — Docker dying *after* Testcontainers' cached endpoint detection surfaces as other exception types (DockerApiException etc.), uncaught by design: catching broader types would relabel image-pull/wait-strategy failures and misdiagnose. Documented boundary (task file "Out of scope"); the pass-through test pins it.
