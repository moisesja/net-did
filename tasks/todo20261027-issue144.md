# Issue #144: dependency upgrades for 3.1.1

## Context

`main` (a563e9b, the #143 merge, so the issue's sequencing precondition is met) restores two vulnerable
transitive packages: `Microsoft.Build.Tasks.Git` 10.0.300 via SourceLink (GHSA-23fw-v26w-5fgq) and
`SSH.NET` 2025.1.0 via Testcontainers (GHSA-q939-rpr3-3284, GHSA-mggc-4xg6-vcxf). Their NU1902/NU1903
audit warnings break the 0-warning gate. Sixteen packages are outdated. FluentAssertions 8+ is
commercially licensed, so the suite moves to AwesomeAssertions (Apache-2.0 fork). `xunit` 2.9.3 is
deprecated, so the suite moves to xUnit v3. The goal is one PR that meets every acceptance criterion
without changing library behavior.

Pre-plan trial: a throwaway worktree off `main` with every upgrade applied.

**Compile and warnings**
- Exactly 3 compile errors, all expected: two `IAsyncLifetime` fixtures and `HaveCountGreaterOrEqualTo`.
- After a full rebuild: 862 × xUnit1051 warnings and 1 × xUnit3003.

**Tests and samples**
- 1,808 of 1,809 unit tests pass.
- The integration suite passes 18/18 against real Anvil, and all 5 samples exit 0.
- The one failure is `Issue101_ArrayValuedDomain_PinnedPipelineRejectsUpstreamLimitation`. Its fixture can no
  longer be built, because DataProofs 1.4.0 rejects `AdditionalProperties["domain"]` as a reserved proof name.

**Package and interop checks**
- `dotnet list` `--vulnerable --include-transitive`, `--outdated` and `--deprecated` are all empty.
- The DIF vectors replay at suite commit f792ce4 is identical to baseline.

**Research agents**
- DataProofs 1.1.1→1.4.0 changes nothing net-did can observe except one logged reason string.
  v1.1.1..v1.3.0 makes zero changes to `DataProofsDotnet.Core`.
- NetCrypto 1.5.0 now accepts high-S secp256k1 in `Verify`. net-did never calls `ICryptoProvider.Verify`,
  and did:ethr and the emulator enforce low-S themselves.
- The FA 7 → AwesomeAssertions 9.6 review found one loosened site: `OnlyContain` is vacuous on an empty
  collection, which affects `AssertNoSentinel`.

### Decisions (approved)
1. Run xUnit v3 through `xunit.v3.mtp-off` 4.0.2 and stay on VSTest. CI, `--filter` syntax and
   `coverlet.collector` keep working unchanged. Moving to MTP mode becomes a follow-up issue.
2. Suppress xUnit1051 in the test projects instead of editing 862 call sites. `AbandonableTaskExtensions.cs:40`
   branches on `ct.CanBeCanceled`, so blanket token threading would move the #109/#122 tests off the
   paths they pin.
3. Fix xUnit3003 properly with a caller-info constructor.
4. Hold no package back.
5. File the pre-existing member-name surrogate → `notFound` bug as a separate issue. It is out of scope here.
